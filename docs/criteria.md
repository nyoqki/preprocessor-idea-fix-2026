# Как проект закрывает критерии

Основа - пункт 10.4 [правил хакатона](https://cloud.mail.ru/public/HPwf/UHMcjpUay),
редакция 06.10.2026. В полуфинале четыре критерия по 5 баллов.
Ниже указано, что сделано и чем проверено. Непроверенные пункты отмечены отдельно.

## 1. Соответствие требованиям

Ученик отправляет боту фото решения. Бот распознаёт строки, проверяет
преобразования через SymPy, находит первый неверный шаг и задаёт наводящий вопрос.
Ошибки попадают в личную карту, по ним собираются задания для тренировки.
В мини-приложении есть карта, история, разбор с фото, тесты и материалы класса.

- [Обработка фото](../src/yasno/bot/handlers/homework.py).
- [Проверка и сохранение разбора](../src/yasno/services/analysis.py).
- [Личные тесты](../src/yasno/services/quizzes.py).
- [API](../src/yasno/api/webapp) и [экраны](../webapp/src/screens).
- [Проверки сценария с фото](../tests/bot/test_homework.py).

Проверен запуск Docker с PostgreSQL и Redis. Браузер с настоящим HTTP API
принял три ответа и сохранил результат после перезагрузки.

**Ещё проверить:** весь путь с нового аккаунта внутри настоящего MAX.
Область проекта - математика; работу с другими предметами не заявляем.

## 2. Пользовательский опыт и дизайн

Плохо распознанную строку можно исправить перед разбором. Подсказку можно
уточнить в диалоге. Тест использует темы и ошибки конкретного ученика.
В интерфейсе есть загрузка, пустые данные, сообщение об ошибке и повтор запроса.
Поддерживаются светлая и тёмная темы, разные размеры экрана и кнопка MAX BackButton.

- [Подсказки и уточнения](../src/yasno/ai/tutor.py).
- [Выбор тем и заданий](../src/yasno/services/quizzes.py).
- [Браузерные проверки](../webapp/tests/browser.mjs).

Прошли 8 групп браузерных проверок: шесть экранов на пяти ширинах,
в двух темах, а также ошибки, повтор, прохождение теста и перезагрузка.
Основной браузерный набор подставляет ответы API; отдельная проверка
использовала настоящий API и БД с тестовой подписью initData.

Настоящая vision-модель распознала 10 из 10 строк на трёх печатных примерах
из [тестового набора](../tests/fixtures/vision_smoke). В соседних JSON лежат
эталонные строки. Реальных ученических работ и личных данных в наборе нет.
Эти числа не показывают точность на рукописных тетрадях.

**Ещё проверить:** дать новичку пройти путь без подсказок команды,
проверить реальные рукописные работы и двух учеников с разной историей ошибок.

## 3. Стабильность и отклик

Обновления MAX поступают в очередь Redis. Повторная доставка не создаёт вторую
задачу. Сохранение разбора и карты выполняется одной транзакцией; повторное
подтверждение не учитывает ошибку дважды. Параллельные ответы завершают тест
с правильными счётчиками. Поздний ответ AI не возвращает данные после `/delete`.

У запросов и обработки есть таймауты. При сбое AI используются повторные попытки
и следующий настроенный провайдер. Права учителя проверяются заново;
согласие проверяется перед сохранением личных данных.

- [Параллельные операции и удаление во время разбора](../tests/services/test_concurrency.py).
- [Таймауты и резервные AI-провайдеры](../tests/ai/test_resilience.py).
- [Ошибки обработки в worker](../tests/worker/test_updates.py).
- [Права, данные и повторные запросы API](../tests/api/test_webapp_db.py).
- [Проверки webhook](../tests/api/test_webhook.py).

Полный набор после оптимизации профиля: **549 тестов прошли без пропусков**.
После возврата серверных настроек отдельно прошли 98 тестов API, worker
и одновременных операций. Ruff, форматирование и mypy также прошли.
Повторное открытие 18 экранов не изменило строку профиля в PostgreSQL;
роль и согласие при этом читаются из БД на каждом запросе.

**Ещё проверить:** задержки и восстановление на рабочем сервере с настоящим AI.
В локальных нагрузочных прогонах были разрывы HTTP-соединений; точная причина
пока не найдена. Смена keep-alive клиента не считается исправлением сервера.
Падение между отправкой уведомления и записью результата также не позволяет
обещать доставку ровно один раз.

## 4. Мобильность архитектуры

MAX-клиент, HTTP API, бизнес-логика, математика, AI и хранение разделены.
Для Chat, Vision и OCR есть отдельные интерфейсы и адаптеры.
Порядок AI-провайдеров задаётся настройками, все сервисы собираются в Docker.

- [MAX-клиент](../src/yasno/max/client.py).
- [AI-адаптеры и выбор провайдеров](../src/yasno/ai).
- [Бизнес-логика](../src/yasno/services).
- [Математическая проверка](../src/yasno/math).
- [Dockerfile](../Dockerfile) и [Compose](../compose.yaml).

Настоящий MAX API проверен чтением данных бота. Настоящие Chat/Vision DeepSeek,
SymPy и PostgreSQL вместе разобрали три печатных примера: ошибка знака найдена
во второй строке, два правильных решения приняты, темы определены верно.
Время этих разборов - 7,04 / 2,43 / 2,88 с, без доставки сообщений через MAX.

**Ещё показать:** рабочие внешние подключения в сдаваемой версии и как добавить
функцию без переделки проекта. Перенос на другой сервер и смена провайдера
не являются отдельными обязательными требованиями пункта 10.4.4.

## Перед сдачей

1. Пройти настоящий MAX: подключение, фото с ошибкой, уточнение, карта и тест.
2. Повторить с другим учеником и другой историей ошибок.
3. Проверить рукописные фото, отказ AI и перезапуск worker.
4. Убедиться, что жюри доступны бот, исходники и последняя версия Docker-образа.

Команды сборки и запуска есть в [README](../README.md).
Автоматические проверки подтверждают перечисленные случаи, но не гарантируют
20 баллов: окончательную оценку выставляет жюри.
