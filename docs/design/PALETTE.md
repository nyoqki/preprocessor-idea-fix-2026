# Палитра для создания экранов

Статус: **пользователь выбрал более контрастное направление и потребовал белые подписи основных кнопок в обеих темах**. Дата: 6 ноября 2026. Точные action-токены ниже уточнены под это требование; повторное согласование перед созданием экранов не требуется.

Используем **B: нейтральная база MAX UI, контрастные синие кнопки с белой подписью**. [Интерактивное сравнение](palette-preview.html) · [изображение обеих палитр](evidence/palette-comparison.png).

## A. Исходная палитра MAX UI

Значения прочитаны из установленного `@maxhub/max-ui` 0.9.0, `dist/styles.css`, и сопоставлены с [официальным исходником](https://github.com/max-messenger/max-ui/blob/c793ccd230bb47e5bf5370cd15a053c8a0be8132/src/styles/variables/appearance.scss). Это токены UI kit; они не гарантируют побитовое совпадение с каждым экраном каждой версии MAX. Рекламный градиент логотипа к ним не приравнивается.

Разделители наследуются из MAX UI, если они декоративны. Граница, необходимая для распознавания интерактивного элемента, должна иметь достаточный контраст; тонкую декоративную линию нельзя автоматически использовать как единственную границу поля.

Основной CTA сохраняет белые текст, иконки и spinner в default/hover/pressed/loading при переключении темы. Бледный голубой остаётся для ссылок и акцентов тёмной темы. У вторичных кнопок собственные контрастные подписи; правило белого текста не распространяется на бледные и прозрачные заливки. В disabled используются нейтральные цвета без имитации активного действия.

Статусы:

| Значение | Светлая: текст / фон | Тёмная: текст / фон |
|---|---|---|
| Найдена учебная ошибка / стоит повторить | `#B4233A` / `#FCEEF1` | `#FF9BAA` / `#361F28` |
| Требуется уточнение / закрепляем | `#945200` / `#FFF3DB` | `#F0C36A` / `#332A19` |
| Проверено / освоено | `#087A2F` / `#EAF7EE` | `#7DDD98` / `#1B3023` |

Смысл статуса всегда дублируется подписью и при необходимости значком. Учебную ошибку не следует оформлять как аварийный сбой приложения. Состояние темы и состояние операции имеют отдельные названия, даже когда используют сходную цветовую пару.

## Контраст проверенных пар

Расчёт: линейная sRGB-яркость, затем `(Lmax + 0.05) / (Lmin + 0.05)`. Значения округлены до двух знаков, для решения о прохождении используется неокруглённый результат. Для прозрачных цветов перед расчётом нужен итоговый compositing.

| Текст | Фон | Контраст | Обычный текст 4.5:1 |
|---|---|---:|---|
| `#FFFFFF` | A `#007AFF` | 4.02:1 | Не проходит |
| A `#007AFF` | тёмная карточка `#25262D` | 3.75:1 | Не проходит |
| A `#1ABE43` | `#FFFFFF` | 2.47:1 | Не проходит |
| A `#FF303C` | `#FFFFFF` | 3.66:1 | Не проходит |
| `#FFFFFF` | B `#0066CC`, обе темы | 5.57:1 | Проходит |
| `#FFFFFF` | B hover `#005CBF`, обе темы | 6.40:1 | Проходит |
| `#FFFFFF` | B pressed `#0052AD`, обе темы | 7.47:1 | Проходит |
| B `#0066CC` | `#FFFFFF` | 5.57:1 | Проходит |
| B `#5AA5FF` | `#25262D` | 5.93:1 | Проходит |
| `#B4233A` | `#FCEEF1` | 5.75:1 | Проходит |
| `#945200` | `#FFF3DB` | 5.51:1 | Проходит |
| `#087A2F` | `#EAF7EE` | 4.96:1 | Проходит |
| `#FF9BAA` | `#361F28` | 7.61:1 | Проходит |
| `#F0C36A` | `#332A19` | 8.56:1 | Проходит |
| `#7DDD98` | `#1B3023` | 8.48:1 | Проходит |
| `#646870` | `#EDEEF2` | 4.82:1 | Проходит |
| `#B2B5BE` | `#25262D` | 7.35:1 | Проходит |

Порог относится к обычному тексту, а не ко всему UI без исключений. Для крупного текста и значимых нетекстовых элементов применяются другие критерии. [W3C: Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

## Переход к созданию экранов

Следующий этап — все шесть экранов, общие компоненты и состояния в двух темах по [PROMPT.md](PROMPT.md). Дополнительный этап выбора цветов не нужен. Эта документация задаёт требования; рабочие экраны в рамках подготовки промпта не изменяются.
