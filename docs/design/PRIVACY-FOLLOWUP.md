# Необходимое серверное исправление: малые группы сводки

Проверено по текущему коду 6 ноября 2026. В этом визуальном изменении backend не редактировался; существующие незакоммиченные изменения AI/математики сохранены.

`src/yasno/worker/reminders.py` применяет `MIN_GROUP_FOR_DIGEST = 2` к группам прогресса недельного digest. `src/yasno/api/webapp/teacher.py` возвращает все распределения `weak/improving/solid` по теме, общий `students_with_gaps` и частую ошибку без аналогичного порога. Авторизация teacher и ограничение своим классом уже реализованы, но они не решают раскрытие единичных агрегатов.

Отсутствие имён и фото не делает маленькую группу полностью анонимной. Например, точные числа 1/0/0 в классе с одним учеником раскрывают индивидуальный результат. Простое скрытие числа 1 в UI не помогает: оно остаётся в ответе API, а иногда вычисляется из общего числа и соседних категорий.

Минимальный отдельный серверный change:

1. Вынести согласованную политику размера групп из worker в общий сервис агрегации и применять её **до сериализации** как к digest, так и к HTTP-сводке.
2. Не отдавать точные значения малой группы ни в распределении темы, ни в `students_with_gaps`, ни в `top_error_type`. Порог 2 из digest — исходная точка совместимости, не доказательство достаточной защиты. Учесть возможность вычислить скрытое значение вычитанием, включая «Нет данных» и общий размер класса.
3. Явно представить состояние «недостаточно данных для групповой сводки». Текущий контракт с точными integer-полями не выражает подавление категорий; нельзя подменять скрытые значения нулём и называть это отсутствием ошибок. Для полного подавления всей сводки можно расширить контракт отдельным признаком, сохранив прежние поля для обычных групп.
4. Добавить серверные тесты: класс из 1 ученика; 1 участник с прогрессом в большом классе; 2+ участников с единичной подкатегорией; единственный тип ошибки; вычисление подавленной категории через дополнение; чужой класс и student/403; согласованность HTTP и digest.

Пока эта отдельная работа не выполнена и не проверена, приложение сообщает только фактическое «без имён и личных работ». Готовность защиты персональных данных и полная анонимность не заявляются. Клиентское оформление не заменяет серверную политику.
