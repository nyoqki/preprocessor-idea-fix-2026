# Проверка реализации

Дата: 6 ноября 2026. Проверка локального React-приложения в Chromium. Настоящий клиент MAX и размещение в Сферуме не проверялись.

## Воспроизведение

```bash
cd /home/jiraya/Projects/yasno/webapp
npm ci
npm run lint
npm run typecheck
npm run build
npm run test:browser
```

`test:browser` использует установленный `playwright-core`, Chromium `/usr/bin/chromium` (переопределяется `CHROMIUM_PATH`) и самостоятельно запускает временные Vite на 5183/5184. В тесте есть два уровня: dev-модель для всех продуктовых состояний и настоящий HTTP-клиент с ответами API, подменёнными на уровне браузера. Это проверка клиентских контрактов, а не работающего FastAPI/PostgreSQL.

Исходник проверки: `webapp/tests/browser.mjs`. Результаты и измерения: [browser-report.json](evidence/implementation/browser-report.json). Скриншоты: [указатель](SCREENSHOTS.md), [визуальная галерея](evidence/implementation/index.html).

Итог: **8 групп браузерных проверок пройдены, ошибок 0**. Проверены 60 сочетаний экран/тема/размер и 24 дополнительные цветовые пары, сохранены 36 скриншотов.

## Выполненные проверки

- `npm run lint`, `npm run typecheck`, `npm run build`.
- Дополнительная production-сборка с `VITE_MOCK=1`: dev-модель и каталог исключены, используется HTTP-клиент.
- Все шесть экранов, обе темы, размеры 360×800, 390×844, 320×568, 768×1024, 1280×800: 60 сочетаний экран/тема/размер. Проверены ширина документа и доступность последнего элемента над нижней навигацией при прокрутке до конца.
- Длинные названия тем и формула с локальной прокруткой. Увеличение CSS zoom до 200% на всех экранах без горизонтальной прокрутки документа.
- Студент с тремя вкладками, учитель с четырьмя; отказ студенту на прямом teacher route.
- Пустые карта, история, материалы и сводка; отсутствие актуального теста; независимая ошибка загрузки теста с сохранением тем; ошибки первой загрузки и восстановление.
- Все технические статусы и содержательные verdict разбора: queued, processing, needs_confirmation, failed, correct, error, review, incomplete, null. Отсутствие error fields не считается успехом.
- Отсутствие/ошибка фото не скрывают строки; повтор загрузки фото; номер 2 совпадает с индексом API 1, меткой на фото и строкой решения.
- Ручное обновление разбора при offline: прежние строки остаются; после подключения повтор работает.
- Поиск без совпадений, очистка поля, ошибки пагинации материалов и истории с сохранением первых записей и успешным повтором.
- 401, 403, 404 с контекстными сообщениями; прямой `startapp=quiz_7`; браузерный возврат на карту.
- Верный/неверный ответ; блокировка двойного клика; объяснение после подтверждения; ручной переход дальше; выход и продолжение; reload и завершение с реальными 4/5; темы ошибок без повторов.
- Сбой до сохранения и потеря сетевого ответа после сохранения. «Проверить и повторить» делает GET, а при наличии сохранённого ответа не отправляет новый POST. Отдельно проверен HTTP-клиент с существующим идемпотентным автоматическим retry POST и восстановлением по GET.
- Истечение теста, в том числе после ошибки отправки/409 и GET восстановления; отсутствие фиктивной генерации нового теста.
- Keyboard focus и Enter для действий; тема меняется без потери ввода; системная тема реагирует на `matchMedia`; reduced motion отключает анимацию skeleton.
- Тестовый Bridge: native BackButton появляется на вложенном маршруте, обработчик вызывается, после выхода обработчики снимаются и кнопка скрывается. Проверена совместимость формы Promise viewport с fallback.
- После прохождения сняты и просмотрены скриншоты всех шести экранов в обеих темах и ключевых состояний. Результаты не выдаются за пользовательское исследование.

## Контраст и основные кнопки

Computed styles проверяются в Chromium для обеих тем:

| Состояние | Фон | Подпись | Контраст |
|---|---|---|---|
| Default | #0066CC | #FFFFFF | 5.57:1 |
| Hover | #005CBF | #FFFFFF | 6.40:1 |
| Pressed | #0052AD | #FFFFFF | 7.47:1 |
| Loading | #0066CC | #FFFFFF, белый spinner | 5.57:1 |

Loading сохраняет высоту обычной кнопки, белую подпись и градиент spinner. У основной кнопки проверен белый цвет иконки. Доступное имя кнопки сохраняется, когда MAX UI скрывает видимый контент во время loading. Disabled оформляется отдельной нейтральной парой.

Дополнительно автоматически проверены реальные вычисленные пары основного/вторичного/приглушённого текста, ссылки, secondary default/hover/pressed, трёх статусов и значимой границы элемента. Прозрачный вторичный текст сначала композится на фактическом фоне. Численные результаты находятся в `contrastPairs` машинного отчёта. Проверенные текстовые пары достигают 4.5:1, граница — 3:1.

После измерения исправлено светлое secondary pressed-состояние: прежнее #C9DFFF давало 4.10:1 с #0066CC; итоговое #DCEAFF даёт 4.57:1. Hover #E1ECFF даёт 4.68:1. Основные заливки и белые подписи не менялись.

Эти проверки не являются полной сертификацией WCAG 2.2 AA. Отдельное исследование с пользователями и полноценный аудит screen reader не проводились.

## Что требует настоящего MAX

- Совпадение с вручную выбранной темой клиента: сейчас подтверждён реактивный системный fallback, документированного механизма темы клиента в просмотренной документации не установлено.
- Нативный внешний chrome, BackButton конкретной версии клиента, поведение при повторном входе через startapp.
- Реальная экранная клавиатура, viewport, safe areas и ориентация на iOS/Android. В браузере проверены responsive размеры; это не эмуляция всех особенностей WebView.
- Возврат в настроенный бот через `openMaxLink`; без username предоставлена инструкция.
- Существующая production-авторизация с подлинным подписанным initData, реальные медиа-ссылки и динамические серверные подсказки.

Серверные и AI/math-файлы не менялись, поэтому Python-тесты в рамках этого изменения не запускались. Выявленную проблему единичных агрегатов сводки нельзя закрыть клиентским кодом; [минимальный серверный follow-up](PRIVACY-FOLLOWUP.md) описан отдельно. До его реализации полная анонимность и готовность защиты данных не заявляются.

Материалы архива прочитаны в отдельной временной папке; слайд продуктового цикла просмотрен визуально. Персональные сведения участников и маркетинговые числа не перенесены в демо. Существующие незакоммиченные изменения пользователя в backend/AI/математике и README сохранены.
