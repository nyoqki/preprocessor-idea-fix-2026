# Дизайн-система «Ясно»

Реализация: 6 ноября 2026. Направление B из [задания](PROMPT.md). Все шесть экранов используют React 19, MAX UI 0.9.0, системную гарнитуру и общий CSS. Наш слой доступности — адаптация проекта, не официальный стандарт Сферума.

## Принципы

Сначала состояние и ближайшее действие. Актуальный тест расположен перед статистикой. Тема описывается словами «Стоит повторить», «Закрепляем», «Освоено»; количество ошибок всегда историческое. Разбор отличает завершение обработки от достоверности результата. Материалы показывают только имеющуюся выдержку. Учитель получает только агрегаты, без переходов в личные работы.

Нейтральный фон и поверхности задают иерархию. Один синий акцент обозначает действие. Учебная ошибка выделяется подписью, номером шага и рамкой. Градиенты, декоративные тени и оценки личности отсутствуют.

## Сопоставление с MAX UI 0.9.0

Публичный API проверен по установленным `.d.ts`, `dist/index.js`, `dist/styles.css` и [документации MAX UI](https://dev.max.ru/ui/). Сгенерированные классы библиотеки не используются как селекторы.

| Токен MAX UI | Роль Ясно |
|---|---|
| `--background-surface` | canvas |
| `--background-primary` | surface |
| `--background-card` | surface-raised |
| `--background-surface-secondary` | surface-secondary |
| `--text-primary`, `--text-secondary`, `--text-tertiary` | text-primary, text-secondary, text-muted |
| `--text-themed`, `--icon-themed` | link |
| `--icon-primary` | text-muted |
| `--button-primary` | action-bg |
| `--states-button-primary-hover/pressed/disabled` | action-hover/pressed/disabled-bg |
| `--controls-active` | link |
| `--gradients-loading-icon-themed-filled/transparent` | link / transparent |

`Action` оборачивает родной `Button`. Только **внутри основной кнопки** `--text-primary-inverse-static` получает `action-label`, а `--states-text-primary-inverse-static-disabled` — `disabled-label`. `--gradients-loading-icon-contrast[-static]-filled/transparent` получают белый/прозрачный белый. Это удерживает белые текст, иконку и spinner при смене темы, не меняя основной текст приложения. В loading остаются фон и геометрия активной кнопки; disabled оформляется нейтрально. Цвета default/hover/pressed задаются явно и проверяются computed styles.

Только внутри вторичной кнопки `--text-primary` получает `secondary-label`, а `--button-secondary-contrast` и его hover/pressed — соответствующие secondary-токены. У установленного `Button variant="secondary"` действительно используются именно эти публичные переменные. `primary-contrast` для CTA не применяется.

Публичные `innerClassNames` используются для содержимого/spinner кнопок, поля/очистки поиска и переносов строк `CellSimple`.

## Размеры и композиция

Отступы собственных элементов: `space-1/2/3/4/5/6/8` = 4/8/12/16/20/24/32 px. Они совместимы с базовым шагом MAX UI. Основной промежуток между секциями 16 px, внутри группы 8–12 px. На планшете — 20 px между секциями.

Радиусы по роли: поле и кнопка 12 px, карточка/список/фото 16 px, бейдж и номер шага 6 px. Сохраняется геометрия родных элементов MAX; выбранные значения делают небольшие метки отличимыми от контейнеров.

Гарнитура `--family-base` MAX UI по платформе. Заголовок 28 px, вопрос 22 px, основной текст 16/24, вторичный 15/21–23, вспомогательные подписи 13/18. Критичные результаты имеют заголовок и обычный читаемый текст. Формулы в шагах — 20 px, гарнитура Cambria Math / Times New Roman; длинный шаг прокручивается **локально**, доступен с клавиатуры и сохраняет математический порядок. Имена тем и условия переносятся без обрезки.

Оболочка ограничена 640 px, с боковыми полями 16 px (12 px на 320). Нижняя навигация ограничена той же шириной, слой 10. Поиск — sticky, слой 5. Под навигацией зарезервированы её высота, safe area и 24 px. Последний элемент доступен при прокрутке до конца. Основные области касания 48 px, выбор ответа 64 px, назад 44 px, вкладка 56 px. Это проектная цель, а не утверждение о минимуме WCAG.

Состояния кнопок и прогресс меняются за 140–160 ms. При reduced motion переходы и пульсация skeleton отключаются. Учебные ошибки не вызывают вибрацию и тряску.

## Компоненты и поведение

- `Action`: единственный базовый компонент действия, семантические primary/secondary/ghost, защита loading от повторного клика, `aria-busy`.
- `Screen`, `ScreenHeader`: один h1, фокус при открытии экрана, браузерная кнопка назад при отсутствии нативной.
- `SkeletonCards`, `ErrorState`, `InlineError`, `EmptyState`: загрузка, ошибка, локальная ошибка операции и пустота; один понятный шаг восстановления.
- `Chip`: текстовый статус с самостоятельной парой foreground/background.
- `Photo`: исходные пропорции, номер шага, загрузка, отсутствие и повтор после ошибки. Увеличение/диалог не добавлены.
- Строки решения: `line.index + 1` на экране, в подсказке и на фото; позиция в массиве не заменяет индекс API.
- Варианты теста: отправка по одному тапу, блокировка повторов, правильность только по серверному ответу, текст «Твой ответ» / «Верный ответ». Результат не сменяется автоматически.
- Сводка: ширина полосы равна `students_total`; показано число учеников с данными и без них. Темы сортируются по числу «Стоит повторить», затем «Закрепляют».

После неоднозначного сбоя POST выбранный вариант удерживается. «Проверить и повторить» сначала читает GET теста: показывает сохранённый ответ, учитывает истечение или повторяет тот же вариант. POST сервера уже идемпотентен. После выхода/reload источником истины остаётся сервер. Демо сохраняет только синтетические ответы в sessionStorage; это не production offline cache.

## Темы, Bridge и запуск

Используется `MaxUI colorScheme`, платформенный режим iOS/Android и реактивный `prefers-color-scheme`. `html/body/root` получают тот же фон. В dev `?theme=light|dark` позволяет проверить тему; в production этот параметр не меняет тему и роль.

Тема MAX вручную не выводится из вымышленных Telegram API. В [документации Bridge](https://dev.max.ru/docs/webapps/bridge) подтверждены `BackButton`, `getViewportSize(): Promise<{width:string,height:string}>` и `openMaxLink`. Они вызываются с feature detection и обработкой отказов; подписки снимаются при выходе. Viewport имеет CSS `100dvh` fallback. `visualViewport` помогает убирать нижнюю навигацию при клавиатуре; safe area остаётся `env(...)` без заявления о полноте поддержки WebView.

`VITE_BOT_USERNAME` — необязательная публичная build-конфигурация. Если задан корректный username, «Открыть чат» использует `openMaxLink` и fallback. Иначе показывается короткая инструкция возврата в личный чат. Username не выводится из токена и не зашит в код.

Демо: `cd webapp && npm run dev:mock`. Каталог: [http://localhost:5173/?catalog=1](http://localhost:5173/?catalog=1). Каталог содержит кнопки, поля, список, статусы, математику, фото, варианты теста и сводку; ссылки открывают все экраны с выбранным сценарием. Он исключён из production. Роль демо задаётся `?role=student|teacher`; в production роль приходит только от сервера.
