## Какие правила использованы

[Официальная страница](https://www.sferum.ru/hackathon_2026) ведёт в
[папку с правилами](https://cloud.mail.ru/public/HPwf/UHMcjpUay).
В ней указан файл "Хакатон Идея Фикс ред. от 06.10.2026.pdf", 250524 байта.
Имя и размер совпадают с файлом в `~/Downloads/AyuGram Desktop/ZzZ.zip`.
Правила прочитаны из локального PDF. Побайтовое совпадение с облачной копией не проверялось.

Также прочитаны гайд, инструкция `oformlenie.md`, презентация, анкета Word
и четыре старых исследовательских файла. Оригиналы не менялись.
Важнее эта редакция правил, чем ранние региональные объявления.
Изменения в закрытом боте организатора не проверялись.

## Срок и состав работы

По п. 8.5 и инструкции из архива, срок - **08.11.2026, 23:59 по Москве**.
В Брисбене это 09.11.2026, 06:59. Отправляет капитан. До конца приёма
можно заменить работу; в боте остаётся последняя версия.

Нужны:

- Ссылка на работающего бота MAX.
- Доступный GitHub с исходниками.
- Docker-образ, который проверяющий может скачать.
- `requirements.txt` с версиями.
- README с командами сборки, запуска и примером CLI.
- Работающий бот и веб-интерфейс с серверной логикой.

Репозиторий, ссылка на бота, образ и инструкции есть. Перед сдачей нужно
скачать именно последнюю версию образа и пройти путь с нового аккаунта.
Браузерное демо с подставными данными этого не заменяет.

П. 9.5 запрещает итоговые материалы, полностью или преимущественно созданные
генеративным AI, включая прототип. Команде нужно проверить свой вклад,
сохранить историю разработки и уметь объяснить код. П. 9.3 требует соблюдать
права на чужие материалы. Ответы опроса с именами детей публиковать нельзя.

## Четыре критерия, максимум 20 баллов

Каждый критерий оценивается от 1 до 5. Это краткий пересказ п. 10.4.

| Критерий                 | Что есть                                                                               | Что ещё проверить                                                                |
| ------------------------ | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Соответствие требованиям | MAX-бот, разбор фото, карта, тесты и мини-приложение                                   | Пройти весь путь в настоящем MAX с новым аккаунтом.                              |
| UX и дизайн              | Правка распознанных строк, подсказки с контекстом, личные задания, повтор после ошибки | Дать новичку пройти путь без помощи; проверить двух учеников с разными ошибками. |
| Стабильность и отклик    | Очередь, ограничения, транзакции, повторные запросы к AI, резервные провайдеры         | Измерить время с реальными фото, проверить отказ провайдера и перезапуск worker. |
| Мобильность архитектуры  | Отдельные слои MAX, API, AI, математики и хранения                                     | Показать готовые внешние подключения и объяснить добавление новой функции.       |

Без проверки в MAX оценка кода - 15/20, подробнее в [strict-review.md](strict-review.md).
Новые функции сами по себе не добавят баллов, если основной путь работает плохо.
Для первого этапа и финала правила также оценивают идею, проблему, актуальность,
новизну, представление и перспективы. Эту шкалу нельзя смешивать с 20 баллами полуфинала.

## Что в материалах расходится с кодом

| Заявление                           | Как работает сейчас                                                                                         |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Любые предметы, пример с линзами    | Проверка и генераторы сделаны для математики. Нужен математический пример.                                  |
| Векторный поиск                     | Используется полнотекстовый поиск PostgreSQL с русской морфологией.                                         |
| Генерация теста по конспекту        | Тесты используют темы и ошибки, текст конспекта в генератор не поступает.                                   |
| Объектное хранилище                 | Файлы лежат на общем Docker volume. S3-адаптера нет.                                                        |
| Данные не покидают РФ               | Это зависит от сервера и выбранного провайдера. Наличие российских адаптеров не определяет место обработки. |
| Списать нельзя ни при каком запросе | Есть проверки утечки ответа, но абсолютной гарантии нет.                                                    |
| Ничего заполнять не нужно           | Нужны подключение и согласие, иногда дата контрольной или правка строки.                                    |
| Весь класс подключается сразу       | Каждый ученик сам открывает личный диалог с ботом.                                                          |
| Ровно за два дня приходит тест      | Напоминание зависит от известной даты контрольной и доступности диалога.                                    |

Подробные правки по страницам есть в [presentation-review.md](presentation-review.md).

## Что показать перед отправкой

1. Подключение ученика и согласие.
2. Фото с известной ошибкой, верный номер строки и подсказка без готового ответа.
3. Уточнение по этой работе и переход к карте с исходным фото.
4. Тест, сохранение ответа и изменение карты. У второго ученика другая история.
5. Материал, поиск, контрольная и уведомление в отдельном тестовом классе.
6. Доступ учителя и отказ обычному участнику, затем отзыв прав администратора.
7. Нечёткое фото, неверный номер строки и отказ AI.
8. `/delete` во время разбора: данные не должны появиться снова.
9. Запуск сдаваемого образа на чистой базе.

Для проверки напоминания не меняйте часы рабочего сервера. Используйте тестовую
базу и фиксированное время в тесте. Учебный эффект можно оценивать после пилота:
как часто ученики сами исправляют ошибку и повторяют ли её через неделю.
