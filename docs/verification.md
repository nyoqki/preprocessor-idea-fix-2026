## Объём автоматических проверок

Браузерный набор: шесть экранов, ширины 320 / 360 / 390 / 768 / 1280 px,
светлая и тёмная темы, пустые состояния, загрузка, сетевые ошибки и восстановление,
прохождение теста, неоднозначный результат POST, сохранённый ответ,
истечение авторизации, глубокие ссылки и жизненный цикл MAX BackButton.
Основной набор использует управляемые ответы API. Дополнительный прогон обращался
к настоящему API запущенного Docker-сервиса без подмены его HTTP-ответов.
В дополнительном прогоне только initData MAX было синтетически подписано тестовым
ключом; это проверка контракта интеграции, а не проверка запуска из настоящего MAX.

Новые проверки охватывают одновременные подтверждения и ответы, удаление во время
анализа, отзыв прав и согласия, переполнение идентификаторов, повреждённые подписи,
слишком большой webhook, утечку ответа в продолжении диалога, лимит уточнений,
длинные сообщения, таймаут worker и восстановление зависшего уведомления.

Один первый браузерный прогон завершился таймаутом ожидания заголовка в группе
пустых/ошибочных состояний тёмной темы. Отдельный повтор и последующий полный
прогон прошли. Таймаут теста не увеличивался; добавлены сведения о маршруте,
снимок при сбое и учёт необработанных JavaScript-ошибок во всех контекстах.
Повторяемость в CI ещё требует наблюдения.

Первый Docker build завершился ошибкой DNS в сети BuildKit. Сборка с
`--network=host` прошла, последующие сборки использовали кэш. Для локальных HTTP-проб
использован `trust_env=False`, поскольку настроенный в окружении прокси возвращал
502 на адрес loopback; напрямую контейнер отвечал 200.

## Воспроизведение

```bash
TEST_DATABASE_URL=postgresql+asyncpg://yasno:yasno@127.0.0.1:55432/yasno_audit .venv/bin/pytest -q
.venv/bin/ruff check
.venv/bin/ruff format --check
.venv/bin/mypy
cd webapp
npm ci
npm run build
npm run lint
npm run format:check
npm run test:browser
npm audit
```

```bash
AI_FAKE=false AI_PROVIDER_ORDER=openai OPENAI_VISION_MODEL=deepseek-flash \
  .venv/bin/python -m yasno.ai.eval tests/fixtures/vision_smoke
docker build --network=host -t yasno:strict-audit .
```

AI-eval обращается к настроенному внешнему провайдеру.
Для другой модели необходимо задать соответствующие переменные окружения.

Для проверок использованы собственные одноразовые контейнеры `yasno-strict-postgres`,
`yasno-strict-redis`, `yasno-strict-api` и базы `yasno_audit` / `yasno_container`.
Существующие контейнеры и базы других проектов не менялись. Тестовые схемы удаляются
самими тестами; временные контейнеры остановлены после проверки. Образ оставлен локально.

Локальные снимки и отчёт браузера — `webapp/artifacts/browser/`, исключены из git.
Оригинальный архив, PDF и Word не изменены. Все 12 страниц презентации просмотрены;
редакционные замечания подготовлены в `presentation-review.md`.
