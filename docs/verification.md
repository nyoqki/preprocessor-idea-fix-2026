готовность, веб-приложение, авторизация и 18 чтений прошли; строка профиля
не менялась. В одном снимке API использовал 109,3 МиБ. Это только API,
без памяти PostgreSQL, Redis, worker и процесса SymPy. Пиковый расход не измерялся.

## Браузер

Проверены шесть экранов на ширинах 320, 360, 390, 768 и 1280 px,
в светлой и тёмной темах. Также проверены пустые данные, загрузка, ошибки,
повтор запроса, неоднозначный POST, завершение теста, перезагрузка,
истечение авторизации и кнопка MAX BackButton.

Основной набор подставляет ответы API. Дополнительный запуск использовал
настоящий API из Docker и PostgreSQL. Только initData подписаны тестовым ключом,
поэтому это не проверка запуска из настоящего MAX.

Первый браузерный запуск один раз не дождался заголовка в тёмной теме.
Отдельный и полный повторы прошли; таймаут не увеличивался.
Добавлены снимок и маршрут при сбое. За повторяемостью в CI ещё нужно следить.

## Повторный запуск

```bash
uv sync --locked
TEST_DATABASE_URL=postgresql+asyncpg://user@localhost/yasno_test uv run pytest -q
uv run ruff check
uv run ruff format --check
uv run mypy
cd webapp
npm ci
npm run build
npm run lint
npm run format:check
npm run test:browser
```

Для тестов нужна отдельная PostgreSQL. Каждый DB-тест создаёт свою схему и удаляет её.
Проверка vision обращается к внешнему провайдеру:

```bash
AI_FAKE=false AI_PROVIDER_ORDER=openai OPENAI_VISION_MODEL=deepseek-flash \
  uv run python -m yasno.ai.eval tests/fixtures/vision_smoke
```

Первой Docker-сборке мешал DNS BuildKit; с `--network=host` она прошла.
Локальные HTTP-запросы выполнялись без прокси (`trust_env=False`),
потому что прокси окружения возвращал 502 на loopback.
Временные базы и контейнеры создавались отдельно от других проектов.
Исходный архив, PDF и Word не менялись.
